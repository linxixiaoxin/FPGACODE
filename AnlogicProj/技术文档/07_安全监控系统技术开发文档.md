# 07 — 安全监控系统技术开发文档

> **所属项目**: AxisesCTRL (四轴伺服驱动器 FPGA)  
> **涉及目录**: `SafetyMonitor/`  
> **关键模块**: SafetyMonitor, RegSpcae_SafetyMonitor

---

## 1. 模块概述

安全监控系统负责实时检测所有故障条件（IPM故障、过流、看门狗超时），管理故障锁存与解除逻辑，并控制PWM使能输出。它是整个伺服驱动器安全功能（STO相关）的FPGA部分实现。

### 1.1 设计指标

| 参数 | 值 |
|------|-----|
| 监控轴数 | 4轴独立 |
| 故障检测类型 | IPM故障、过流 (OC)、看门狗超时 |
| 故障响应延迟 | ≤ 1μs (100MHz 同步链) |
| 看门狗分辨率 | 1μs (10ns × 100) |
| 默认看门狗周期 | 1000μs (1ms) |

### 1.2 模块层次

```
SafetyMonitor.v
└── RegSpcae_SafetyMonitor.v   ← 全部安全逻辑 + 寄存器
```

## 2. 故障检测架构

### 2.1 故障输入信号

| 信号 | 来源 | 描述 | 每轴独立 |
|------|------|------|---------|
| `AxisN_IPMFault` | 外部IPM模块 (IPMFo_L取反后) | 智能功率模块故障 (过温/短路/欠压) | ✓ |
| `AxisN_OC` | CurrentSample | 电机相电流过流 | ✓ |
| `WatchDog_overflow` | 内部计数器 | 看门狗超时 | 全局 |

### 2.2 故障同步链

```verilog
// IPM故障: 2级同步
reg IPMFault_sync1, IPMFault_sync2;
always @(posedge clk) begin
    IPMFault_sync1 <= AxisN_IPMFault;
    IPMFault_sync2 <= IPMFault_sync1;
end

// OC故障: 直接使用 (已同步)
// OC来自CurrentSample, 在100MHz域产生, 无需额外同步
```

### 2.3 故障锁存逻辑

```verilog
// 实时故障状态
FaultStateRT = {WatchDog_overflow, 7'd0,
                Axis4_IPMF, Axis4_OC, Axis3_IPMF, Axis3_OC,
                Axis2_IPMF, Axis2_OC, Axis1_IPMF, Axis1_OC};

// 锁存故障状态 (保持直到软件清除)
always @(posedge clk or negedge rst) begin
    if (!rst)
        FaultStateLocked <= 0;
    else begin
        for each fault bit:
            if (FaultStateRT[bit] && ProtectFuncEnable[bit])
                FaultStateLocked[bit] <= 1'b1;     // 锁存
            else if (ProtectLockedFlagClear[bit])
                FaultStateLocked[bit] <= 1'b0;     // 软件清除
            else if (!ProtectFuncEnable[bit])
                FaultStateLocked[bit] <= 1'b0;     // 禁用保护自动清除
    end
end
```

## 4. PWM安全控制

### 4.1 PWMUNLOCK 生成逻辑

```verilog
// 每轴独立计算
for AxisN:
    if (FaultStateLocked[AxisN_IPM] || FaultStateLocked[AxisN_OC] || WatchDog_overflow_Lock)
        AxisN_PWMUNLOCK = 0;    // 任何故障 → 锁定PWM
    else
        AxisN_PWMUNLOCK = PWMOutputChannelEN[AxisN];  // 无故障 → 通道使能

// STOout: 安全转矩关闭输出 (当前固定为0)
assign STOout = 1'b0;
```

**PWMUNLOCK = 0 的效果**:
1. CarrierModule 硬件自动清除 PWMEN 和 BootstrapInit
2. 所有6路PWM输出强制为0 (关断)
3. 即使MCU尝试重新使能PWM, 硬件也会立即清除

### 4.2 PWM输出通道使能 (地址 0x000F)

| 位 | 名称 | 描述 |
|----|------|------|
| [15:4] | (保留) | — |
| [3] | Channel4_EN | 轴4 PWM输出使能 |
| [2] | Channel3_EN | 轴3 PWM输出使能 |
| [1] | Channel2_EN | 轴2 PWM输出使能 |
| [0] | Channel1_EN | 轴1 PWM输出使能 |

## 5. 看门狗定时器

### 5.1 硬件实现

```verilog
// 1μs 定时器
reg [6:0] Timer_1usCNT;     // 0→99 循环 (100MHz / 100 = 1MHz)
wire Timer_1usPluse = (Timer_1usCNT == 99);

// 看门狗计数器
reg [15:0] WatchDog_CNT;    // 以 μs 为单位计数
parameter WatchDog_Period_Default = 100;  // 默认 1000μs = 1ms

always @(posedge clk or negedge rst) begin
    if (!rst)
        WatchDog_CNT <= 0;
    else if (WatchDogFeed_Valid)          // 写0x5AA5喂狗
        WatchDog_CNT <= 0;
    else if (Timer_1usPluse && WatchdogEN)
        WatchDog_CNT <= WatchDog_CNT + 1;
end

// 超时检测
assign WatchDog_overflow = WatchdogEN && (WatchDog_CNT >= WatchDog_Period);
```

### 5.2 喂狗协议

```verilog
// 向地址0x0007写入0x5AA5喂狗
wire WatchDogFeed_Valid = CS && RDLWRH && (ADDR == 7) && (WRDATA == 16'h5AA5);
```

## 6. 软件系统复位

### 6.1 复位协议

```verilog
// SysResetCTRL (地址 0x0003)
// 写: 作为系统复位控制
// 读: 返回 FreeRunCNTer[22:7]

always @(posedge clk) begin
    if (CS && RDLWRH && ADDR == 3) begin
        if (WRDATA == 16'hFFAA)
            SysResetCTRL <= 16'hFFAA;
        else
            SysResetCTRL <= 16'd0;
    end
end

assign SysResetSig = (SysResetCTRL == 16'hFFAA);
```

效果: SysResetSig → SysPLL → 系统复位 (保持2μs后释放)

## 7. 寄存器地址映射

### 7.1 通道基地址: `0x0800`

### 7.2 完整寄存器表

| 偏移 | 名称 | 位宽 | R/W | 复位值 | 描述 |
|------|------|------|-----|--------|------|
| 0x00 | FPGALoadedFlag | 16 | R | 0x5AF0 | FPGA加载标志 (只读固定值) |
| 0x01 | Version_H | 16 | R | 0x0100 | 固件版本号高位 |
| 0x02 | Version_L | 16 | R | 0x0001 | 固件版本号低位 |
| 0x03 | SysResetCTRL / FreeRunCNTer | 16 | R/W | — | W: 写0xFFAA复位; R: 自由计数器[22:7] |
| 0x06 | WatchDog_Period | 16 | R/W | 100 | 看门狗超时周期 (μs) |
| 0x07 | WatchDog_Feed | 16 | W | — | 写 0x5AA5 喂狗 |
| 0x08 | FaultStateRT | 16 | R | — | 实时故障状态 |
| 0x09 | FaultStateLocked | 16 | R | — | 锁存故障状态 |
| 0x0A | ProtectFuncEnable | 16 | R/W | 0x0000 | 保护功能使能掩码 |
| 0x0B | ProtectLockedFlagClear | 16 | W | — | 锁存故障清除掩码 |
| 0x0F | PWMOutputChannelEN | 16 | R/W | 0x0000 | PWM输出通道使能 (bit3:0) |

### 7.3 FaultStateRT 位定义 (0x0008, 只读)

| 位 | 描述 |
|----|------|
| 15 | WatchDog_overflow (实时看门狗溢出) |
| 14:8 | 保留 (读为0) |
| 7 | Axis4_IPMFault (实时) |
| 6 | Axis4_OC (实时) |
| 5 | Axis3_IPMFault (实时) |
| 4 | Axis3_OC (实时) |
| 3 | Axis2_IPMFault (实时) |
| 2 | Axis2_OC (实时) |
| 1 | Axis1_IPMFault (实时) |
| 0 | Axis1_OC (实时) |

### 7.4 FaultStateLocked 位定义 (0x0009, 只读)

与 FaultStateRT 相同的位排列，但每个位都带有 `_Lock` 后缀（故障锁存直到软件清除）。

## 8. 故障处理流程

### 8.1 软件故障处理流程

```
1. 中断触发 (或轮询 FaultStateRT 0x0008)
2. 读取 FaultStateLocked 0x0009 → 确定锁存故障类型
3. 读取 FaultStateRT 0x0008 → 确认故障是否仍存在
4. 如果故障已消失 (RT=0, Locked=1):
   → 写 ProtectLockedFlagClear 0x000B 清除对应位
   → 检查 FaultStateLocked 确认已清除
   → 重新使能 PWMOutputChannelEN 0x000F
5. 如果故障仍存在 (RT=1, Locked=1):
   → 不能清除，等待故障消失
```

### 8.2 看门狗处理流程

```
1. MCU周期性 (例如每500μs) 写0x5AA5到地址0x0007
2. 如果MCU死机/通信中断 → 看门狗计数器持续递增
3. 到达WatchDog_Period → WatchDog_overflow = 1
4. 锁存 → 所有轴PWMUNLOCK = 0 → 电机停机
5. 复位或重新喂狗后恢复
```

## 9. 状态机总结

```
                        ┌─────────┐
         上电复位       │   IDLE   │
    ┌──────────────────→│ (无故障) │
    │                   └────┬─────┘
    │                        │ 故障检测
    │                   ┌────▼─────┐
    │                   │  FAULT   │  ← 任一轴IPM故障/OC/看门狗
    │                   │ (锁存)   │
    │                   └────┬─────┘
    │                        │
    │                   PWMUNLOCK=0
    │                   强制PWM关断
    │                        │
    │                   ┌────▼─────┐
    │    软件清除 ←─────│ RECOVERY │
    │    (写0x000B)     │ (等待清除)│
    │                   └────┬─────┘
    │                        │
    └────────────────────────┘
```

## 10. 安全关键设计点

1. **故障锁存**确保了瞬态故障也能被可靠捕获和记录
2. **硬件PWM互锁**: 即使软件出错试图使能PWM, PWMUNLOCK=0时硬件也会自动清除PWMEN
3. **看门狗独立于MCU**: FPGA内部独立运行, MCU死机不影呴看门狗超时
4. **故障源冗余**: IPM故障 (功率器件) + OC (电流采样) 双重保护覆盖功率级和采样级
5. **STO预留**: STOout端口已预留但当前未激活 (固定为0), 后续可接入外部STO回路
